# PROJECT DESC.

This, qr-stream, is a project that aims to send and receive data by use of QR codes as the name suggests

I intend to create QR codes from chunks of the data and stream them over a stream of say 30fps depending and we will improve as time moves by
there isn't much to say about the project as I feel its self-describing

## PLAN

I intend to build the project in phases, and using some pre-assembled libraries other than doing everything from scratch as I am taking baby steps
towards my CS based TIE degree and portfolio

### Phase-1

This will be simply understanding the fundamentals and getting the project running, so chunking the data and creating QR codes for it.
This will either be saved frame by frame(the easier route for a beginner) or streamed directly(a bit harder to implement, I think, haven't really researched on that)

once we have the frames then we will line them up and stream them so the whole file can now appear as a video.

ps: this phase is entirely to make the video and just see it like stream or sth, no too much science here
### Phase-1-b

This will build on phase 1 as this will now transform the project from a text only project to a more sophisticated system adding the ability to accept files
with extensions and transmitting those, I think the most intriguing or awaited part is like streaming a video say like 2MB, that would really be cool!

### Phase 2

This would be a scaling phase as here we are not just adding a feature but we are improving our working, here I intend to add an encryption system as rn
anyone who can like isolate frame by frame of our data can read our data, we dont want that so I would add an encrypting system to the project. 

ofc at this point we would need a reader, and I intend to fix that in either in phase 1 or 1-b esp. phase 1 coz its the only measure that we have 
succeeded, sending sth and seeing it on the other end
